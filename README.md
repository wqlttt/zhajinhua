# 炸金花

多人联机炸金花，WebSocket 实时对战。手机竖屏优化。

## 玩法

和朋友输入**同一个 4 位房间号**即进同一桌。房间不存在会自动创建，全员离线 2 分钟后自动回收。

每桌最多 6 人，2 人即可开局。所有人点准备后 5 秒倒计时开牌。

## 规则

牌型从大到小：

| 牌型 | 说明 |
|---|---|
| 豹子 | 三张同点，AAA 最大 |
| 同花顺 | 同花色连续，AKQ 最大 |
| 金花 | 同花色不连续 |
| 顺子 | 不同花色连续，A23 最小 |
| 对子 | 两张同点，第三张比大小 |
| 单张 | 散牌逐张比点 |

可选规则 `235 杂花通杀豹子`（默认开启），但遇到其它牌型按单张算。

### 闷牌与注额

**闷牌下注是明牌的一半。** 内部统一按「明注等价值」记账，闷牌玩家实付减半：

| 当前单注 | 闷牌实付 | 明牌实付 |
|---|---|---|
| 10 | 5 | 10 |
| 40 | 20 | 40 |

**加注按差价补齐。** 单注提高后，已经下过注的人轮到时只补差额，不重复付全额。例：单注 10 时你跟了 10，别人加注到 40，你只需再补 30。

比牌需要「补齐差价 + 一倍当前单注」，且必须先看牌——闷牌不能比牌。平局时发起方输。

最小加注为当前单注加一个底注。加注区间由服务端计算下发，客户端滑条直接使用两端值。

单注上限默认取起始筹码的一半（1000 筹码 → 上限 500），保证连续加注后仍有空间。筹码不够最小加注时，操作栏会给出全下。

### 其它

- 底注人人相同，不分闷明，不计入当轮下注
- 超时 30 秒：闷牌自动跟注，明牌自动弃牌
- 默认 4 轮封顶，到达后强制开牌
- 筹码只存在内存中，服务重启即重置

## 本地运行

```bash
npm install
PORT=8080 node server.js
```

浏览器打开 `http://localhost:8080`。

## 配置

全部通过环境变量：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 8080 | 监听端口 |
| `ANTE` | 10 | 底注 |
| `START_CHIPS` | 1000 | 初始筹码 |
| `MAX_SEATS` | 6 | 每桌座位数 |
| `CAP_BET` | 起始筹码的一半 | 单注上限（明注口径） |
| `MAX_ROUND` | 4 | 封顶轮数，到了强制开牌 |

超时秒数、倒计时秒数在 `table.js` 的 `DEFAULTS` 里。

## 部署

`jinhua.service` 是 systemd unit，服务以非 root 的 `jinhua` 用户运行，内存上限 320M。

```bash
# 上传代码到 /opt/jinhua 后
npm ci --omit=dev
cp jinhua.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now jinhua
journalctl -u jinhua -f    # 看日志
```

配置写在 `/etc/jinhua.env`（权限 600）：

```
PORT=8080
ANTE=10
START_CHIPS=1000
MAX_SEATS=6
```

### 安全提示

房间号就是唯一凭证，4 位数字只有一万种组合，**公网部署等于房间对外公开**——外人可以枚举房号进入你的房间。仅建议在可信网络或配合反向代理的访问控制使用。

未配置 HTTPS 时通信为明文。前面套 Nginx/Caddy 做 TLS 后，客户端会自动切换到 `wss://`，代码无需改动。
